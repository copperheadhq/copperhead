## 11. Review findings: multi-line secret redaction

- [x] 11.1 The PEM pattern added in 7.1 needs its header and footer in one string, but `repl.ts`'s `log()` split on `\n` *before* `fileLine()` redacted each line, so a real multi-line private key was written verbatim into `.copperhead/runs/repl-*.log` — the transcript seam was safe only because it JSON-stringifies first (newlines become `\n` escapes inside one string). Found in review and reproduced directly: whole-string redaction yields `[REDACTED]`, per-line redaction yields the key intact. **This falsified the AC-4.1 extension this change added.** Fixed: `log()` now redacts the whole message before splitting (`fileChunk` replaces `fileLine`; the chunk carries its own newlines, so the bytes written are unchanged); history and the terminal still get raw text, only the persisted file is redacted. Verified: new regression test in `test/repl.test.ts` drives a real multi-line PEM through `runRepl` and asserts no key material, and no `BEGIN PRIVATE KEY`, reaches the log file while the surrounding lines survive.
- [x] 11.2 Defence in depth for a *truncated* block (output cut between header and footer), which the full-block pattern cannot match by construction. Added a header-anchored fallback consuming only the base64 body lines that follow. Two hazards checked rather than assumed: **(a) ReDoS** — each repetition must begin with a newline, which is outside the body charset, so the match is unambiguous and linear; probed at 1–2 MB pathological inputs (20k body lines 9ms, 20k near-miss lines 1ms, 2 MB flat tail 1ms). **(b) over-redaction** — the first draft had no length floor and ate the word `not` off the start of the following prose line (caught by the new test, not by inspection); a `{16,}` floor fixes it, since real body lines are 64 chars. A bare 40-char git SHA on its own line is untouched, because the pattern requires the PEM header above it. Verified: two new cases in `test/safety.test.ts`. Honest limit, stated in the code comment: this bounds the damage, it is not a second complete defence — it still needs the header in the same string, which is why 11.1 is the real fix.
