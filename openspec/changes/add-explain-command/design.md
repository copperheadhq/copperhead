# add-explain-command: Design

## Context

`listSymbols`, `listNets`, and `pinNets` already walk the schematic for `init`, drift, and REPL `/parts` `/nets`. `explain` is that data, addressed by one query, plus optional doc context from `BOM.md` / `PINOUT.md`.

## Goals / Non-Goals

**Goals:**

- One command answers "what is U1 / what is on GND / what is U1.GPIO14 connected to?"
- Stable `--json` for scripts and MCP hosts later.
- Same lookup inside the REPL as `/explain`.

**Non-Goals:**

- No LLM "why is R7 here?" narrative. Doc mentions are excerpts, not generated rationale.
- No board-side footprint lookup (that is a separate sexp enumerator).
- No new agent tool. The command is a human/CI inspect surface.

## Decisions

- **D1: Resolve against the schematic, then decorate from docs.** KiCad files are as-built facts (same truth precedence as `sync`). A BOM row that disagrees with the schematic is still shown; `explain` does not run drift.
- **D2: Closed query grammar, one hit.** Order: `REF.PIN` (number or name), exact refdes, exact net, unique pin name. Ambiguous pin names fail with "use REF.PIN" rather than guessing.
- **D3: No `kicad-cli` dependency.** The command uses the read-only sexp walker, so it runs anywhere `init`'s schematic parse runs, including machines where ERC is unavailable.
- **D4: Suggestions on miss, never a stack trace.** Prefix and substring matches against refdes and net names, capped at five.

## Risks / Trade-offs

- [Geometric `pinNets` is not a full netlister] → documented: T-junctions and buses can miss, same as PINOUT.md generated by `init`. Not a new parser.
- [Query `GND` matching both a net and a part] → refdes wins if both exist; the fixture has no such clash. A later flag can force kind if needed.

## Migration Plan

Additive command. Repos with no schematic configured get a clear error pointing at `copperhead init`.
